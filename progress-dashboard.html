Where things stand: the core edit loop is real and working — open a file, edit it live, click between code and 3D shapes in either direction, drag a shape with a translate/rotate/scale gizmo to rewrite its source in place (inserting a new wrap if it had none, and doing so "in place" relative to any existing translate rather than orbiting the world origin), toggle mirror or pick a color from the toolbar, or insert a new primitive. Placement (position/rotation/scale) is now a real three.js transform on each shape's pivot group rather than baked-in geometry, which is what makes local-space rotate/scale legitimate — the rotate gizmo has a Local/World toggle as a result (scale stays local-only, translate stays world-only; see build notes for why). Mirror is folded into scale's sign (an axis-aligned mirror and a matching negative scale are the same matrix) but always round-trips through real `mirror()` calls in source, never a literal negative `scale()`. Every top-level statement in a file is its own independently-rendered, clickable, draggable object.

Known gaps (expected, not bugs): no parameter panel yet for editing a selected node's own arguments directly (the one remaining M5 piece), no booleans/extrusions UI (M6-M7), no custom-module detection (M8), no fillets/chamfers (M12, stretch goal — OpenSCAD has no native edge-selective rounding; see PLAN.md). Selection is positional and can reset after a structural edit (a stable-ID fingerprint comes later, once multi-node dragging needs it). The placement architecture assumes canonical color→translate→rotate→mirror→scale ordering regardless of how a file is actually written — documented in PLAN.md, fails visibly rather than silently if violated.
