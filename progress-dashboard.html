Where things stand: the core edit loop is real and working — open a file, edit it live, click between code and 3D shapes in either direction, drag a shape with a translate/rotate/scale gizmo to rewrite its source in place (inserting a new wrap if it had none, and doing so "in place" relative to any existing translate rather than orbiting the world origin), toggle mirror or pick a color from the toolbar, edit a selected node's own call arguments (including position) directly in a generic parameter panel, insert a new primitive, or select two+ shapes (ctrl/cmd-click to toggle one, shift-click to range-select) and combine them with a real Union/Difference/Intersection — all three independently verified with real CSG results (a fused blob, a shared-volume lens, a hollowed-out cavity), not just source-text changes — with the base (click-order-first) shape and the tool(s) being combined/subtracted rendered in distinct colors with a matching toolbar legend. A shape can also be flagged with any of OpenSCAD's four modifier characters (highlight, ghost, show-only, disable), each with real render/visibility behavior, not just a source-text toggle. The camera only re-fits on file-open or an explicit "Reset View" click, not on every edit. Placement (position/rotation/scale) is now a real three.js transform on each shape's pivot group rather than baked-in geometry, which is what makes local-space rotate/scale legitimate — the rotate gizmo has a Local/World toggle as a result (scale stays local-only, translate stays world-only; see build notes for why). Mirror is folded into scale's sign (an axis-aligned mirror and a matching negative scale are the same matrix) but always round-trips through real `mirror()` calls in source, never a literal negative `scale()`. The parameter panel is schema-free — it reflects whatever arguments (named or positional) a call actually has in source, with no hardcoded per-primitive knowledge. Every top-level statement in a file is its own independently-rendered, clickable, draggable object (until merged into a boolean group — see gaps below). Linear Extrude / Rotate Extrude toolbar buttons insert a pre-wrapped 2D profile that gets all the same editing for free (extrude mechanics needed no new code at all), and bare 2D primitives (Square/Circle) — previously silently broken — now render too, via a hairline-extrude fallback on the existing WASM pipeline rather than a separate geometry path. Sketch mode now has three working slices: pick a sketch plane — a global plane (XY/XZ/YZ) *or* click any flat face of an existing solid to derive a plane from its origin/normal — and the camera animates to a true straight-on orthogonal view with rotation locked (pan/zoom still work); then click to place points — a live preview (markers + connecting line) tracks each click, and "Finish Sketch" commits a real `polygon()` statement (wrapped in the plane's own `translate()`/`rotate()` when needed) that's immediately selectable with a working gizmo and parameter panel, no special-case integration required. Existing shapes correctly stop intercepting clicks while sketching, so drawing works reliably even directly on top of other geometry. "Linear/Rotate Extrude" now actually extrude the selected sketch in place (previously they always inserted an unrelated default shape, regardless of selection — a real gap caught in testing). Also found and fixed two more real render bugs while finishing this slice: the bare-2D render fallback was nesting file context (module/function definitions) inside its own synthetic extrude wrapper, breaking any bare-2D node in a file that also defines a module or function (very likely the real cause of the original "rendered 3 of 4 nodes" report on a plain triangle); and "Linear/Rotate Extrude" was nesting a plane's `rotate()` on the wrong side of the new extrude block, rotating the 2D profile before extrusion instead of the finished solid after, which OpenSCAD silently can't represent — affected every plane except XY, including the already-shipped XZ/YZ ones, and was only caught because full pipeline testing (draw → finish → extrude, not just draw → finish) is now standard practice before calling a slice done. Both fixed and the full pipeline reverified end-to-end on all four plane kinds. The viewport now has a CAD-style orientation nav cube in its top-right corner (click a face, edge or corner to swing the camera there; arrows around it turn or roll the view in 90° steps) and a Shaded / Shaded + edges / Wireframe dropdown under it, all driven by the same camera-animation primitive sketch mode uses. Building it exposed that the viewport had always been Y-up rather than OpenSCAD's Z-up (the default example's upright cylinder rendered lying down); it is Z-up now. Earlier still: found and fixed a systemic bug affecting every programmatic edit in the app, not just sketch mode: Monaco's content-change event fired on the app's own internal setValue() calls indistinguishable from real typing, silently double-rendering every gizmo commit, toolbar insert, boolean, and modifier toggle since M2/M4 — fixed with the same isFlush-guard pattern already used for M5's cursor-reset fix. Newest: on-plane editing — select an already-placed sketch (bare, or the profile under its Linear Extrude) and "Edit Sketch" re-opens it on the plane it was drawn on with its points as draggable handles (click near an edge to add a vertex, double-click to delete one, Undo), then "Save Sketch" rewrites just that polygon's points in place and the solid re-renders with the new profile. Verifying it turned up a subtle r3f behavior that silently starved drags of pointer moves (a stopped hover keeps stopping every later move over the same object), fixed, and handles now draw on top of neighboring solids. Still no draw-time snapping, and one profile per sketch session. M5, M6, and M7 are all fully done; M7.5 is in progress.

Known gaps (expected, not bugs): a merged boolean group's children aren't independently selectable/draggable yet (clicking one selects the whole group — moved to M9's "nested selection & drill-in navigation" scope, not tracked under M6 anymore), no draw-time snapping (remaining M7.5 scope), no custom-module detection (M8) — so positional parameter-panel arguments show as `#1`/`#2`/... rather than a module's real parameter names, since resolving that is M8's job — no fillets/chamfers (M13, stretch goal — OpenSCAD has no native edge-selective rounding; see PLAN.md). Selection is positional and can reset after a structural edit (a stable-ID fingerprint comes later, once multi-node dragging needs it). The placement architecture assumes canonical color→translate→rotate→mirror→scale ordering regardless of how a file is actually written — documented in PLAN.md, fails visibly rather than silently if violated.
